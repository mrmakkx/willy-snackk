# Refonte V2 Willy Snack — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remplacer entièrement le style visuel et le contenu du site Willy Snack (V1) par la refonte V2 (design handoff externe) : nouvelle direction visuelle sombre, nouvelles sections (bandeau, à propos, avis, CTA horaires), carte filtrable avec fiche plat en modale, vrai contenu métier.

**Architecture:** Toujours 3 pages HTML statiques (`index.html`, `menu.html`, `contact.html`) avec header/footer dupliqués. `css/style.css` entièrement réécrit (nouveaux tokens). Nouveau fichier de données `data/menu.js` (tableau JS des plats) consommé par `js/menu-page.js` pour générer dynamiquement les filtres et la liste de la carte, plus la fiche plat en modale. `js/nav.js` gère le menu mobile du header (remplace `js/menu.js` de la V1).

**Tech Stack:** HTML5, CSS3 (variables, Grid, Flexbox, `clamp()`, `backdrop-filter`, animations CSS), JavaScript vanilla (génération DOM depuis un tableau de données, `URLSearchParams`, gestion de modale), Google Fonts (Anton, Karla, Azeret Mono).

**Explication (concepts nouveaux) :**
- `text-transform: uppercase` sur les titres : le texte est écrit en casse normale dans le HTML (lisible, correct pour les lecteurs d'écran) mais s'affiche en majuscules — c'est purement visuel.
- `@keyframes` + `animation` : définit une séquence d'états CSS (`from`/`to`) qu'un élément traverse dans le temps — la base des animations CSS.
- `@media (prefers-reduced-motion: reduce)` : media query qui détecte une préférence système ("réduire les animations", accessibilité) plutôt qu'une taille d'écran.

- [ ] **Étape 1 : Créer `js/menu-page.js`**

```js
const filterBar = document.getElementById('filter-bar');
const dishList = document.getElementById('dish-list');

const categories = ['Tout', ...new Set(MENU_DATA.map((dish) => dish.cat))];

const params = new URLSearchParams(window.location.search);
let activeCategory = params.get('cat') || 'Tout';
if (!categories.includes(activeCategory)) {
  activeCategory = 'Tout';
}

function renderChips() {
  filterBar.innerHTML = '';
  categories.forEach((cat) => {
    const chip = document.createElement('button');
    chip.className = 'chip' + (cat === activeCategory ? ' chip--active' : '');
    chip.textContent = cat;
    chip.addEventListener('click', () => {
      activeCategory = cat;
      renderChips();
      renderDishes();
    });
    filterBar.appendChild(chip);
  });
}

function renderDishes() {
  dishList.innerHTML = '';
  const dishes = activeCategory === 'Tout'
    ? MENU_DATA
    : MENU_DATA.filter((dish) => dish.cat === activeCategory);

  dishes.forEach((dish) => {
    const row = document.createElement('button');
    row.className = 'dish-row';
    row.innerHTML = `
      <div class="dish-row__thumb photo-placeholder">PHOTO</div>
      <div class="dish-row__info">
        <div class="dish-row__top">
          <span class="dish-row__name">${dish.nom}</span>
          <span class="dish-row__price">${dish.prix}</span>
        </div>
        ${dish.desc ? `<p class="dish-row__desc">${dish.desc}</p>` : ''}
      </div>
    `;
    row.addEventListener('click', () => openModal(dish));
    dishList.appendChild(row);
  });
}

function openModal(dish) {
  // Complete a la Task 10
}

renderChips();
renderDishes();
```

**Explication (concepts nouveaux) :**
- `new URLSearchParams(window.location.search)` lit les paramètres après le `?` de l'URL courante ; `.get('cat')` récupère la valeur de `cat` (ou `null` si absent).
- `new Set(MENU_DATA.map((dish) => dish.cat))` extrait toutes les catégories présentes dans les données, puis `Set` élimine automatiquement les doublons (chaque catégorie n'apparaît qu'une fois) ; `[...]` (spread) reconvertit ce `Set` en tableau utilisable.
- `document.createElement` + `innerHTML` construisent des éléments HTML depuis JavaScript, à partir des données — c'est le principe d'un rendu "piloté par les données" (data-driven), la base de tous les frameworks JS modernes (React, Vue, etc.), ici fait à la main.
- Les *template literals* (`` `...${dish.nom}...` ``) permettent d'insérer des variables directement dans une chaîne de caractères.

Remplacer la fonction `openModal` (placeholder) par :

```js
function openModal(dish) {
  modalPhoto.textContent = `PHOTO — ${dish.nom}`;
  modalTitle.textContent = dish.nom;
  modalPrice.textContent = dish.prix;
  modalDesc.textContent = dish.desc;
  modalDesc.style.display = dish.desc ? '' : 'none';
  modalOverlay.classList.add('modal-overlay--open');
  document.body.style.overflow = 'hidden';
  modalClose.focus();
}

function closeModal() {
  modalOverlay.classList.remove('modal-overlay--open');
  document.body.style.overflow = '';
}

modalClose.addEventListener('click', closeModal);

modalOverlay.addEventListener('click', (event) => {
  if (event.target === modalOverlay) {
    closeModal();
  }
});

document.addEventListener('keydown', (event) => {
  if (event.key === 'Escape' && modalOverlay.classList.contains('modal-overlay--open')) {
    closeModal();
  }
});
```

**Explication (concepts nouveaux) :**
- `document.body.style.overflow = 'hidden'` empêche le défilement de la page pendant que la modale est ouverte (sinon on pourrait scroller "derrière" la fenêtre modale) ; on le retire (`= ''`) à la fermeture.
- `modalClose.focus()` déplace le focus clavier sur le bouton fermer dès l'ouverture — important pour l'accessibilité (un utilisateur au clavier/lecteur d'écran doit atterrir dans la modale, pas rester "derrière").
- `event.target === modalOverlay` vérifie qu'on a cliqué précisément sur le fond (l'overlay), pas sur le panneau de la modale lui-même — sinon cliquer n'importe où dans la fiche plat la refermerait.
- L'écouteur `keydown` est posé sur `document` (pas sur la modale) car la touche Échap doit être détectée où que soit le focus sur la page.
